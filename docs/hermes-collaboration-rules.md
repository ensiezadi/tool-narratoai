# NarratoAI 协作守则

Created: 2026-06-01
Last updated: 2026-06-01 17:29:17 CST

**沉默与简短**
- 执行类指令（跑脚本、改配置、查状态）直接做，不复述用户已经说过的背景。
- 调试请求优先围绕：路径、关键报错、环境差异。三步内定位不到再展开说明。
- 问答题能一句话讲清就一句话，不凑段落。

**主动提出计划**
- 任务涉及 3 步以上、需要跨日、或涉及外部依赖时，才提计划。
- 日常增删改查、已确认的流水线步骤：不提计划，直接执行。
- 计划最多 3-5 条，每条必须对应可验证动作。

**输出长度**
- 微信/即时消息：核心结论 + 必要上下文，不超过 200 字。
- 报告/分析/长回复：先给结论，再按需展开；超过 500 字主动标注。
- 纯执行反馈：只报状态和路径，不写过程报告。
- Hermes 作为副手时，默认反馈不超过 5 条；Codex 负责取舍和落地。

**什么值得进 wiki**
- 有复用价值的决策（选型、放弃的方案、配置逻辑）。
- 踩过的坑和解决方案（不是临时调试日志）。
- 流水线架构变更和接口约定。
- 项目约定和工具链约束。

**文档时间维护**
- 新建项目文档必须写 `Created` 和 `Last updated`。
- 修改已有结论、命令、状态、路径或外部依赖时，同步更新 `Last updated`。
- 只改错别字、格式或无语义变更时，可以不更新时间。
- 写入 wiki raw 时保留 `created`，并补 `last_updated`，避免跨会话读到旧状态。

**不看、不记、不扩展**
- 已知事实不再解释一遍。
- wiki 已有的内容不复读。
- 与主线无关的问题：简短敷衍，不延伸。
